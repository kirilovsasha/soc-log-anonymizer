# Runbook аналитика SOC

Одностраничный порядок работы с **SOC Log Anonymizer** (GUI/CLI exe)
перед отправкой логов во **внешнюю LLM**.

Подробности: [шпаргалка](CHEATSHEET.md) · [ложные срабатывания](FALSE_POSITIVES.md) ·
[шифр mapping](MAPPING_ENCRYPTION.md) · [Windows EXE](WINDOWS_EXE.md).

---

## 1. Перед первым запуском

1. Положите рядом с exe: `soc_log_anonymizer.json` (из релиза) и при
   необходимости `portable.flag` (данные рядом с exe, не в AppData).
2. Создайте **соль** один раз на кейс/смену (длинная случайная строка) —
   файл `salt.txt` только в профиле пользователя или на шифрованном
   носителе. **Не** в OneDrive / общий диск / тикет.
3. SmartScreen на unsigned exe — нормально для PyInstaller; берите сборку
   из внутреннего каталога ПО / подписанный релиз.

---

## 2. Поток GUI (типичный разбор инцидента)

1. Откройте лог или вставьте фрагмент (`Ctrl+O` / вставка).
2. Убедитесь, что подхвачены соль и конфиг (орг, allowlist, телефоны РБ).
3. **Анонимизировать** → просмотрите подсветку и таблицу соответствия.
4. Если gatekeeper/качество красные — правьте allowlist/конфиг или
   вырежьте прозу с ФИО вручную (инструмент **не** маскирует имена в тексте).
5. Скопируйте **только** анонимизированный текст во внешнюю LLM.
6. Ответ LLM вставьте в левое окно → **Де-анонимизировать** (тот же mapping).
7. После кейса: **Очистить всё** / закройте окно (сессия чистится по таймауту).
   Mapping на диск — только если нужен повтор; иначе не сохраняйте.

Большие файлы (≳ 50 МБ): согласитесь на превью + sidecar `*.anon.log`
или перейдите на CLI.

---

## 3. Поток CLI (массово / пайплайн)

```bat
:: Анонимизация с блокировкой небезопасного вывода
soc-log-anonymizer-cli.exe anonymize -i raw.log -o clean.log ^
  --salt-file salt.txt --save-mapping map.json --fail-on-unsafe --stats

:: (рекомендуется) шифрование mapping
soc-log-anonymizer-cli.exe anonymize -i raw.log -o clean.log ^
  --salt-file salt.txt --save-mapping map.json --fail-on-unsafe ^
  --mapping-passphrase "секрет" 

:: Ответ LLM обратно
soc-log-anonymizer-cli.exe deanonymize -i reply.txt -o restored.txt ^
  --mapping map.json --mapping-passphrase "секрет"
```

Коды возврата: `0` ок · `1` ошибка · `2` unsafe при `--fail-on-unsafe`
(не отправляйте `clean.log` в LLM).

Гигантские логи: добавьте `--stream` (лучше NDJSON, не один huge JSON).

## 4. Salt и mapping — правила

| Артефакт | Что это | Правила |
|---|---|---|
| `salt.txt` | ключ псевдонимов | как пароль; ACL пользователя; одна соль = одни псевдонимы |
| `map.json` | исходное ↔ псевдоним | = ключ деанонимизации; шифруйте (`--mapping-passphrase` / `--mapping-dpapi`); удалите после кейса |
| `clean.log` | можно во внешнюю LLM | только после `verify` / `--fail-on-unsafe` = 0 |
| audit log | кто/когда/счётчики | без значений; включайте в конфиге при необходимости комплаенса |

Одинаковая соль + один mapping между файлами кейса → корреляции в LLM
сохраняются. Другой кейс — новая соль (или явная политика переиспользования).

---

## 5. Чеклист перед отправкой в LLM

- [ ] В LLM уходит **только** анонимизированный текст / `clean.log`
- [ ] GUI: подсветка и таблица просмотрены; CLI: exit code **0** с `--fail-on-unsafe`
- [ ] Нет ФИО/внутренних ID в свободном тексте (вырезаны или в JSON-полях)
- [ ] Allowlist не «широкий» (не замаскированы лишние служебные токены намеренно — ок; чувствительные — нет)
- [ ] Partial PHONE/PAN/IBAN приемлем политикой (иначе `mask_strategies` → `full`)
- [ ] Mapping/соль не вложении тикета, не в чате LLM, не на общем диске
- [ ] После кейса: очистка GUI / удаление или шифрованное хранение mapping

## 6. Если что-то пошло не так

| Симптом | Действие |
|---|---|
| GUI молча не стартует | `%APPDATA%\SOC Log Anonymizer\gui_error.log` (portable — рядом с exe) |
| «Красный» verify на безобидном hex | см. [FALSE_POSITIVES.md](FALSE_POSITIVES.md); allowlist / `residual_scan` |
| Нужен свой формат поля | [CUSTOM_PATTERNS.md](CUSTOM_PATTERNS.md) |
| Деанонимизация «ломает» ответ | тот же mapping и та же соль, что при anonymize |
